# C 语言位操作四条：置位 / 清零 / 翻转 / 判断

> 配置 STM32 寄存器每天都要写几十遍的操作。核心思想只有一个：**用"掩码（mask）"只动目标位，不影响其他位。**

## 0. 前置概念

**位编号从 0 开始，从右往左数。** 以 8 位数据 `10110001` 为例：

```
位号:  7  6  5  4  3  2  1  0
数值:  1  0  1  1  0  0  0  1
```

**掩码 = 只有目标位为 1 的数**，用移位生成：

```c
uint8_t mask = 1 << 3;   // 二进制 00001000，即"第3位的掩码"
```

`1 << n` 就是把 1 左移 n 位。建议写 `1u << n`（u 表示无符号数），避免符号位带来的意外。

---

## 1. 置位（Set）：把某一位变成 1

```c
reg |= (1u << n);
```

用**或运算 `|`**，规则：

| a | b | a \| b |
|---|---|--------|
| 0 | 1 | **1** |
| 1 | 1 | **1** |
| x | 0 | **x 原样保留** |

关键：`或1` 一定变 1，`或0` 保持不变——目标位被强制置 1，其他位不动。

手工演算，把 `10110001` 的第 2 位置 1：

```
  10110001        原数据
| 00000100        掩码 1<<2
----------
  10110101        结果
```

STM32 实例（让 PA0 输出高电平）：

```c
GPIOA->ODR |= (1u << 0);
```

---

## 2. 清零（Clear）：把某一位变成 0

```c
reg &= ~(1u << n);
```

四条里**唯一需要两个运算符**，最容易写错。分两步理解：

- 掩码先取反：`~(00001000)` = `11110111`（目标位为 0，其余位全为 1）
- 再做**与运算 `&`**，规则：

| a | b | a & b |
|---|---|-------|
| 0 | 0 | **0** |
| 1 | 0 | **0** |
| x | 1 | **x 原样保留** |

`与0` 一定变 0，`与1` 保持不变——目标位被强制清 0，其他位不动。

手工演算，把 `10110001` 的第 7 位清 0：

```
  10110001        原数据
& 01111111        ~(1<<7)
----------
  00110001        结果
```

STM32 实例（让 PA0 输出低电平）：

```c
GPIOA->ODR &= ~(1u << 0);
```

GPIO 还提供**原子操作寄存器 BSRR**，一条赋值直接搞定，点灯推荐：

```c
GPIOA->BSRR = (1u << 0);         // 置位（BS 段，低16位）
GPIOA->BSRR = (1u << (0 + 16));  // 清零（BR 段，高16位）
```

---

## 3. 翻转（Toggle）：0 变 1，1 变 0

```c
reg ^= (1u << n);
```

用**异或运算 `^`**（两边不同结果为 1，相同为 0），规则：

| a | b | a ^ b |
|---|---|-------|
| 0 | 1 | **1**（翻转） |
| 1 | 1 | **0**（翻转） |
| x | 0 | **x 原样保留** |

`异或1` 必翻转，`异或0` 不变。LED 闪烁的经典写法：

```c
GPIOC->ODR ^= (1u << 13);  // 蓝板 PC13 灯状态反转
```

手工演算，翻转 `10110001` 的第 0 位：

```
  10110001
^ 00000001
----------
  10110000
```

## 4. 判断（Test/Get）：读出某一位是 0 还是 1

```c
if ((reg & (1u << n)) != 0) { /* 该位为1 */ }
```

与上掩码后，**其他位全部被 0 屏蔽，只剩目标位的原值**：结果非 0 说明该位是 1，结果为 0 说明是 0。

```
  10110001        原数据
& 00010000        掩码 1<<4
----------
  00010000  ≠ 0   → 第4位是1

  10110001
& 00100000        掩码 1<<5
----------
  00000000  == 0  → 第5位是0
```

注意：`&` 的结果是**掩码本身**（如 0x10），不保证等于 1。想要规范的 0/1 值，右移归一化：

```c
uint8_t bit4 = (reg >> 4) & 1u;   // 结果只可能是 0 或 1
```

判断按键输入的实例：

```c
if ((GPIOA->IDR & (1u << 0)) == 0) {
    // PA0 读到低电平（按键按下，通常需要上拉）
}
```

## 5. 四个宏 + 一次操作多个位

工程里一般封装成宏（STM32 标准库 `stm32f10x.h` 中就是这么定义的）：

```c
#define SET_BIT(reg, n)  ((reg) |=  (1u << (n)))
#define CLR_BIT(reg, n)  ((reg) &= ~(1u << (n)))
#define TGL_BIT(reg, n)  ((reg) ^=  (1u << (n)))
#define GET_BIT(reg, n)  (((reg) >> (n)) & 1u)
```

一次操作多位，把掩码"或"在一起：

```c
reg |=  (1u<<2) | (1u<<5);   // 第2、5位同时置1
reg &= ~((1u<<2) | (1u<<5)); // 第2、5位同时清0
```

## 6. 新手最常踩的 4 个坑

1. **清零忘记取反**：写成 `reg &= (1u<<3)`，结果只保留第 3 位、其他位全清 0，灾难性 bug。
2. **用 `=` 代替 `|=`/`&=`**：`GPIOA->ODR = (1<<0)` 会把其他 15 位全写成 0。置位/清零是"读—改—写"，必须用复合赋值符。
3. **判断时漏括号**：C 语言中 `!=` 优先级高于 `&`，`reg & (1<<3) != 0` 会被解析成 `reg & ((1<<3) != 0)`。务必写 `(reg & (1u<<3)) != 0`。
4. **混淆位运算和逻辑运算**：`&` 对每一位操作，`&&` 只看真假；按位取反用 `~`，逻辑非用 `!`，不能互换。

## 7. 自测题（先写在纸上再对答案）

`uint8_t d = 0b10110001;`

1. 置位第 2 位 → `10110101`
2. 清零第 7 位 → `00110001`
3. 翻转第 0 位 → `10110000`
4. 判断第 4 位 → 1；第 5 位 → 0

---

**一句话记忆：置位或 1（`|=`），清零与反（`&= ~`），翻转异或（`^=`），判断与掩码（`&`）。**
