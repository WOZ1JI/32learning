# STM32 启动流程：复位后到 main() 之间发生了什么

> 对应计划：阶段1 W1「整理 main 之前启动流程笔记」。面试常问："main 之前发生了什么？"

## 总览（4 步）

```
上电/复位
   ↓ ① 硬件自动：取向量表（无代码参与）
   ↓ ② Reset_Handler：准备C运行环境（startup_stm32f10x_hd.s）
   ↓ ③ SystemInit：配置系统时钟72MHz（system_stm32f10x.c）
   ↓ ④ __main：堆/标准库初始化 → 跳转
 main()   ← 我们的代码从这里开始
```

## ① 硬件自动取向量表（纯硬件行为）

复位后 CPU 固定从 FLASH 起始地址 `0x08000000` 开始，这里放着**中断向量表**，前两项是定死的约定：

- 第 0 项（`0x08000000`）= **栈顶地址** → 硬件自动装入 SP 寄存器
- 第 1 项（`0x08000004`）= **Reset_Handler 的地址** → 装入 PC，跳过去执行

**为什么**：C 函数的局部变量、函数调用全靠栈，CPU 必须先知道"栈在哪"才能跑任何 C 代码；程序总得有个固定入口，约定就是向量表前两项。

## ② Reset_Handler（启动文件里的一段汇编）

`startup_stm32f10x_hd.s` 中的 Reset_Handler 依次做两件事：

- 把 **.data 段初值从 FLASH 搬到 RAM**：有初值的全局变量（如 `int a = 5;`），初值 5 存在 FLASH 里，RAM 上电内容是随机的，必须搬过去
- 把 **.bss 段清零**：没初始化的全局变量（如 `int b;`）能默认为 0，就是这里保证的

**为什么**：让 RAM 状态符合 C 语言规则（全局变量有初值/默认为 0），否则程序行为不可预测。

## ③ SystemInit()（库函数）

配置**系统时钟**：外部 8MHz 晶振 → PLL 倍频 → SYSCLK = **72MHz**。

**为什么**：复位后芯片默认只用内部 8MHz 慢速时钟跑，先把主频提上来，程序和延时才按 72MHz 设计。

## ④ __main → main()

`__main` 是 C 库的入口（不是我们写的 main），负责初始化堆、标准库，完成后**跳转到我们写的 main()**。

## 对应文件（Keil 工程目录）

| 文件                       | 内容                                                               |
| ------------------------ | ---------------------------------------------------------------- |
| `startup_stm32f10x_md.s` | 向量表 + Reset_Handler 汇编（搬 data / 清 bss / 调 SystemInit / 跳 __main） |
| `system_stm32f10x.c`     | SystemInit：时钟配置到 72MHz                                           |

## 一句话记忆

**取栈顶 → 跳复位中断 → 搬初值清零 → 配好 72MHz 时钟 → 进 main。**
